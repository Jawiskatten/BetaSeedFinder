# Deadbush15 V12

V12 is a conservative candidate-stage filter for Java 26.3. It combines a necessary Badlands-family biome check from pinned Cubiomes with a vanilla-matched feature RNG upper bound. It does **not** produce confirmed bushes, exact terrain, or a discovered 15-block record. The research and known gaps are documented in [RESEARCH_V12.md](RESEARCH_V12.md).

## Build

Run these commands in PowerShell from `D:\Yes\Deadbush15\deadbush15`:

```powershell
powershell -ExecutionPolicy Bypass -File .\build_v12.ps1
.\deadbush15_v12.exe --self-test
```

The build uses the vendored xpple/cubiomes pin at `b99f6e472018cab903a096697117aab9d9170a19`. The small self-test checks both published XZ rows against the Badlands biome necessary condition and RNG upper bound. The separate Java runtime comparison and its expected values are recorded in `RESEARCH_V12.md`.

## Score and resume

Start from candidates already generated by V4/V7/V9. For example:

```powershell
Set-Location D:\Yes\Deadbush15\deadbush15
.\deadbush15_v12.exe --input .\v7_badlands.csv --output .\v12_upper_bound.csv --index 75
```

The default index is 75 only for continuity with earlier candidate files; V12 has **not** proved that this is the global index for every biome feature context. Search a range when needed:

```powershell
.\deadbush15_v12.exe --input .\v7_badlands.csv --output .\v12_index_range.csv --index-range 64 96
```

To continue an interrupted run, repeat the same input, output and index settings with `--resume`:

```powershell
.\deadbush15_v12.exe --input .\v7_badlands.csv --output .\v12_upper_bound.csv --index 75 --resume
```

V12 writes each scored row immediately and records a `.meta` signature beside the output. Resume requires the same input path, file size, modification time, and index range. Keep the source CSV unchanged during the run.

`POSSIBLE` means every target XZ is individually possible under at least one biome-filter branch and the candidate row has some shared Badlands-family biome Y. It does not guarantee that the same branch generated all points, that the Y offsets agree, or that terrain/support/air checks place any bush. `NO_COMMON_BADLANDS_Y` safely rejects rows where no shared biome Y exists; `EXCLUDED_BY_RNG_XZ` is only conclusive for the supplied feature index or range. A `POSSIBLE` row must be checked using exact vanilla-generated blocks before being reported as a discovery.

## Measurement and known gaps

On this Windows host, the 1,000-row `v7_badlands.csv` sample ran at about **1,852 candidates/s** with index 75; 567 passed the upper bound. Of the five previously failed V9 rows, V12 safely excluded seed `178096580` from the modeled XZ placement stream; the other four still passed the loose upper bound. Retained V10 saved-block results show actual same-Y Badlands maxima of 2, 1, and 2 for seeds `114006365`, `134574834`, and `176410742`. This demonstrates why V12 cannot claim a hit from RNG/biome compatibility alone.

V12 does not yet solve new seed/coordinate pairs, calculate the global feature index from vanilla registries, evaluate exact `WORLD_SURFACE_WG`, test support blocks and air in complete vanilla chunks, or use the RX 7800 XT. No server-per-seed loop is used. No new seed is claimed.
